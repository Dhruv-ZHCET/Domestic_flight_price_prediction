What this means

The winning local approach is an out-of-fold-optimized, class-conditional convex average of independent tree ensembles. Each first-level model made predictions for records excluded from its fold’s training set. Class-specific blending weights are derived from OOF training labels only; the same corresponding fold models predict test records, averaged across five folds.

Important: these are local validation scores, not hidden Kaggle scores. The official evaluation metric has not been provided; RMSE is provisional. In a pure MAE competition the Extra Trees model is preferable. Selecting many models from one dataset introduces model-selection optimism, so do not assume hidden scores exactly equal OOF scores.

Honest robustness tests and uncertainty

Flight-group holdout stress test: Extra Trees RMSE 14,959; LightGBM 15,241; CatBoost 13,771. This intentionally tests flights not seen in training, a substantially more difficult setting than random folds. Only 0.90% of supplied test rows contain unseen exact flight codes, so neither protocol alone perfectly represents the hidden set.

Meta weight crossfit: 5-way crossfit of class-specific blend weights gave RMSE 10,213. This is a useful stability check, though it is not fully nested CV.

Bootstrap: for 1,000 paired resamples of the OOF residuals, the blend-minus-ExtraTrees RMSE difference had a 95% percentile interval of -502 to -185. This is a resampling uncertainty assessment on fixed OOF predictions, not a fresh model-training bootstrap.

Feature selection and importance

Feature ablations on one fixed validation split changed Extra Trees RMSE from 9,788 with all features to approximately 13,204 when flight identifiers were entirely omitted. Shuffling feature values on a holdout provides additional evidence that flight class, flight number, prefix, stop count and class–airline interaction dominate. Correlated route indicators can show low individual importance even when routes carry substantial collective information.

Modeling protocol and safeguards

  1. Drop id from predictor features; use it only to match Kaggle submission rows.
  2. Construct flight prefix/number, route, route×class, time-pair, stop-related interactions, days-left nonlinearities and missing-value flags without target access.
  3. Fit categorical encoders and numeric imputers only within each CV training fold.
  4. Use class-aware stratified five-fold splits with fixed random seed for comparisons.
  5. Train standard linear/poly Ridge, decision tree, bootstrap bagging, random forest, extra trees, histogram boosting, LightGBM, XGBoost and CatBoost; neural networks excluded.
  6. Generate OOF errors and preserve average predictions on unseen test.csv. Never train on the provided test set.
  7. Compare simple fixed blends with constrained class-specific optimized blends and additional held-out-flight stress testing.
  8. Keep high-price Business tickets: clipping them as outliers may greatly damage RMSE.
